## 1. 这是什么

AnnaWathe 是构建在原版 Wathe 之上的**扩展框架 Mod**。它做两件事：

**第一，把关卡"换底板"。** 原版 Wathe 里，扩展想改本能透视颜色、想插入自己的胜利条件、想加心情任务、想自己画 HUD，都必须往 Wathe 的内部类里写 Mixin，彼此冲突、随版本失效。AnnaWathe 把这些位置全部接管下来，改造成统一的**注册式 API**：扩展只注册"规则"，不再碰 Mixin。

**第二，自带一套原版加强玩法。** 在提供接口的同时，AnnaWathe 自己也是这些接口的第一个使用者：它重写了杀手商店定价、重做了心情下降节奏、加了 5 个新任务、加了任务点透视、把疯魔模式改造成可配置的 profile、重绘了欢迎与结算界面、加了尸体死亡信息。所以它既是"框架"，也是"玩法 Mod"。

它**不新增**任何职业、物品或方块。原版 Wathe 的平民 / 杀手 / 义警 / 孤行者（Loose End）四大阵营与全部原有物品保持原样。

**规模：** 158 个 Java 文件、6574 行代码；8 个 CCA 组件；48 个 Mixin；对外 API 共 70 个文件、约 105 个注册型扩展点。

## 2. 运行环境与安装

| 项目 | 要求 |
| --- | --- |
| Minecraft | 1.21.1（构建与运行都锁定此版本） |
| Java | 21 |
| 加载器 | Fabric Loader 0.17.2 或兼容版本 |
| 基础 Mod | **原版 Wathe `1.3.2-1.21.1` ~ `1.4.1-1.21.1`**（同时支持旧版 1.3.2 与最新 1.4.1） |
| 必需依赖 | Fabric API、Cardinal Components API 6.1.1 |
| 环境 | 双端 —— 客户端和服务端都必须安装 |
| 软兼容（可选） | HarpyModLoader（装上后自动启用两个兼容 Mixin） |

### 安装步骤

1. 安装 Fabric Loader 0.17.2+ 与 Fabric API。
2. 把**原版 Wathe** 放入 `mods/` —— 1.3.2 或 1.4.1 均可，AnnaWathe 同时兼容这两个版本。
3. 把 `annawathe-1.0.0-1.21.1.jar` 放入 `mods/`（客户端与服务端都要放）。
4. 启动时确认日志里没有 `was not registered through mod metadata or plugin`（这是 CCA 元数据缺失的典型报错）。

### 支持的 Wathe 版本

AnnaWathe 同时支持 **Wathe 1.3.2 与 1.4.1**，即整个 `1.3.2 ~ 1.4.1` 区间。

- **运行时**：装 1.3.2 或 1.4.1 都能正常游玩，两者机制均已适配。
- **依赖声明**：推荐的写法是 `"wathe": ">=1.3.2-1.21.1 <=1.4.1-1.21.1"`，把上界钉在已验证的 1.4.1，避免将来更新的 Wathe 版本被静默接受。

> **说明（写作本文档时的工程状态）：** 本工程 `gradle.properties` 与 `libs/` 仍以 `wathe-1.3.2-1.21.1.jar` 作为**编译**依赖，因此 SDK 中看到的 `fabric.mod.json` 声明为 `"wathe": ">=1.3.2-1.21.1"`——它只限制了**下界**，语义上已经允许 1.4.1 及更高版本运行。若要让上界约束真正生效，需要把该声明改成上面的推荐写法。除此之外，1.3.2 只是编译基线，**不代表 AnnaWathe 只能在 1.3.2 上运行**。

### 重要警告

> **禁止同时加载自改版 Wathe jar 与 AnnaWathe。**
> AnnaWathe 只搭配原版 Wathe。自改 Wathe（例如 `Wathe - 副本1`）与 AnnaWathe 是两条独立维护线，同时加载会导致启动崩溃或机制错乱。
> 同理，**不要同时保留两个 AnnaWathe 版本**；测试前先删除旧 jar。

## 3. 它与 Wathe 及其他扩展的关系

| 项目 | 类型 | 与 AnnaWathe 的关系 |
| --- | --- | --- |
| **Wathe: Murder Mystery**（doctor4t） | 基础 Mod | AnnaWathe 的**唯一基础依赖**，1.21.1 上的谋杀悬疑社交玩法核心 |
| **AnnaWathe**（本工程） | 扩展框架 + 规则集 | 接管 Wathe 的可扩展点，提供注册式 API，并自带加强玩法 |
| **Kin's Wathe** | 内容型扩展 | 主要**加职业**（7 平民 + 5 杀手 + 3 中立）、加词条、加配置界面，依赖 HarpyModLoader |
| **Wathe: Extended** | 内容/配置型扩展 | 主要**加指南书 GUI、加词条、加地图工具、加配置屏幕**，并修一批 Wathe 与扩展的 bug |
| **Noelle's Roles / Stupid Express / Starry Express** | 内容型扩展 | 加职业、加独立胜利、加装饰与指南 |

**关键区别：** Kin's Wathe 与 Wathe: Extended 是"往游戏里加东西"，AnnaWathe 是"换掉游戏底下的规则并开放接口"。如果你想要更多职业，装前者；如果你想让自己的扩展不必再写 Mixin，或者想要重定价商店、重做心情节奏、任务点透视这类底层调整，用 AnnaWathe。

AnnaWathe **不内置** NoellesRoles / StupidExpress 的具体职业规则——那些职业的胜利条件与任务由各自扩展通过 AnnaWathe 的 API 注册。

## 4. 玩法特性总览

### 4.1 核心玩法改造

| 特性 | 说明 |
| --- | --- |
| **独立定价的杀手商店** | 12 项商品价格全部由 AnnaWathe 自己维护，**刻意不读取**原版 `GameConstants.SHOP_ENTRIES`，方便独立调平衡 |
| **多货币经济** | 支持注册任意货币、AND/OR 组合价格、被动收入、任务收入；默认只启用金币 |
| **心情节奏重做** | 采用自改 Wathe 的数值：每 tick 下降 `1/4000`（约 3 分 20 秒清空），完成任务回复 `0.4`；**多任务不再成倍加速下降** |
| **精神崩溃死亡** | 心情归零真的会死，死因 `wathe:mental_breakdown`；世界级开关可关闭 |
| **5 个新任务** | 蹲下、奔跑、坐下、保持不动、远离人群（详见 §5） |
| **任务点透视** | 5 类任务点穿墙线框显示，`Y` 键开关 |
| **疯魔模式 profile 化** | 疯魔变成可注册 profile：自定义时长、护盾、武器、临时物品、锁栏、皮肤与背景音 |
| **结算界面重绘** | 欢迎公告与胜负结算重写：动态列数、头像、死亡标记、独立胜利双分区、自适应缩放 |
| **尸体死亡信息** | 尸体显示"死亡时间 + 死因 + 死者身份"，默认旁观/创造视角可见 |
| **开局免碰撞** | 对局开始后默认 30 秒内玩家之间不碰撞，避免开局挤成一团 |
| **调试变形** | 管理员可把玩家变成任意在线玩家的外观，支持限时与永久、跨回合保存 |

- 以"玩法存活"语义切换 creative / spectator（`/annawathe:gamemode`）；

- 玩家外观变形（限时 / 永久 / 全体 / 查询 / 清除）。

## 5. 心情与任务机制详解

### 5.1 心情数值（与自改 Wathe 一致）

| 常量 | 值 | 含义 |
| --- | --- | --- |
| 基础下降速率 | `1 / 4000` 每 tick | 满心情到零约 **3 分 20 秒**（200 秒） |
| 任务完成回复 | `0.4` | 完成一个真实心情任务 |
| 多任务是否叠加 | **否** | 无论持有 1 个还是 3 个任务，每 tick 只扣一份 |
| 任务槽扩容阈值 | `0.51` / `0.17` | 心情 > 0.51 时 1 个槽；0.17~0.51 时 2 个槽；≤ 0.17 时 3 个槽 |
| 崩溃警告阈值 | `0.15` | 低于此值时屏幕出现抖动警告文字 |
| 任务上限 | 3 | `MAX_TASKS` |
| 首次任务延迟 | 600 tick（30 秒） | `TIME_TO_FIRST_TASK` |
| 补发任务冷却 | 600~1200 tick 随机（30~60 秒） | 无任务时按此冷却抽取下一个任务 |

> **为什么不用原版数值：** 原版 Wathe（1.3.2 与 1.4.1 均如此）的下降更慢、单次任务回复更多（`0.5`）。AnnaWathe 固定采用自改 Wathe 的节奏，源码注释明确写了这一点，避免运行时又退回原版手感。

**可调接口：** `MoodApi.setDrainMultiplier(float)` 在上述基础下降值上乘算；`MoodApi.protectFromDrain(ticks)` 临时暂停下降；`MoodApi.setMoodDeathEnabled(bool)` 是世界级开关。

### 5.2 内置任务（9 个）

所有 9 个任务都**进入随机池**，权重默认均为 `1.0`，并且会按"抽到次数"衰减——抽到越多，下次抽中的概率越低。

| 任务 ID | 翻译键 | 完成条件 | 关联任务点 |
| --- | --- | --- | --- |
| `wathe:sleep` | `task.sleep` | 睡觉累计 **160 tick（8 秒）** | 床位 |
| `wathe:outside` | `task.outside` | 处于可见天空下累计 160 tick | — |
| `wathe:eat` | `task.eat` | 吃到食物（瞬时完成） | 餐盘 |
| `wathe:drink` | `task.drink` | 喝下鸡尾酒（瞬时完成） | 鸡尾酒盘 |
| `annawathe:shift` | `annawathe.task.shift` | 潜行（`isSneaking()`）累计 160 tick | — |
| `annawathe:run` | `annawathe.task.run` | 疾跑（`isSprinting()`）累计 160 tick | — |
| `annawathe:sit` | `annawathe.task.sit` | 坐在座位上累计 160 tick | 座位 |
| `annawathe:stay` | `annawathe.task.stay` | 每 tick 位移平方 ≤ `1.0E-4`（约 0.01 格）且在地面或载具上，累计 160 tick | — |
| `annawathe:away` | `annawathe.task.away` | **12 格**内没有其他局内存活玩家，累计 160 tick | — |

前 4 个是原版任务的包装（`BuiltInMoodTasks.Legacy`），后 5 个由 AnnaWathe 新增（`Timed` 系列，计时器仅在条件满足时递减）。

游戏内提示文案（语言文件实装）：

- 真实任务：`annawathe.task.feel`「你觉得应该」+ 任务文本；
- 伪装任务：`annawathe.task.fake`「你可以假装」+ 任务文本；
- 任务文本：蹲一下 / 去跑步 / 去坐一下 / 保持不动 / 离人远一点 / 完成一个未知任务。

### 5.3 任务点

| 任务点类型 | ID | 颜色 | 识别对象 |
| --- | --- | --- | --- |
| 床位 | `annawathe:bed` | `#57D6FF` | 床方块（自动折算到床头半块） |
| 食物托盘 | `annawathe:food_tray` | `#61D95C` | 饮料盘中的食物 |
| 鸡尾酒托盘 | `annawathe:cocktail_tray` | `#FF85A8` | 饮料盘中的鸡尾酒 |
| 座位 | `annawathe:seat` | `#7AF4E1` | 可乘坐方块 |
| 对应房门 | `annawathe:keyed_door` | `#FFF79B` | 带钥匙名的小门 |

**扫描范围被严格限制**：只扫描"列车重置模板区域平移后"与地图 `playArea` 的交集，扩展的扫描 handler 每次只判断当前方块，不允许自行全图扫描。

**透视行为：**

- 默认按键 **`Y`**（可在按键设置里改，类别显示为 Wathe），开关时聊天栏上方给出绿/红提示；
- 局内存活玩家只看到**自己当前任务**关联的任务点；旁观 / 创造视角看到全部已注册类型；
- 房门默认**不显示**，只有当你主手拿着 `wathe:key` 钥匙、且钥匙的 LORE 首行与该门钥匙名一致时才显示；
- 相机距离 3 格以内会显示类型标签；多类型用 ` / ` 连接。

任务点数据由服务端整表扫描后通过专用 S2C 包同步到客户端，玩家加入与对局初始化完成时各发一次。

### 5.4 精神崩溃死亡

心情降到 0 且开关打开时，玩家会因 `wathe:mental_breakdown`（精神崩溃）死亡。判定**刻意放在任务完成结算之后**——因为完成一个任务可能在同一 tick 把心情拉回零以上，先结算再判定才不会误杀。

- 语言文件：`death_reason.wathe.mental_breakdown`「精神崩溃」、`replay.death.wathe.mental_breakdown.died`「%s 死于精神崩溃」；
- 开关：`/wathe:moodEffectDeath [true|false]`；
- 关闭后心情仍会下降、任务仍会发放，但不会致死。

### 5.5 卡任务处理

系统会记录每个任务的"卡住次数"。当同时持有 ≥2 个任务且全部卡满 6 次，或恰好只持有 1 个任务且卡满 4 次时，会自动删除卡住的任务并重置冷却，避免玩家被无法完成的任务锁死。

### 6.1 默认杀手商店价格表

价格全部由 AnnaWathe 独立维护，**不读取原版 `GameConstants.SHOP_ENTRIES`**。

| 分类 | 商品 | 价格（金币） |
| --- | --- | --- |
| 武器 | 匕首 Knife | 100 |
| 武器 | 左轮 Revolver | 250 |
| 武器 | 手雷 Grenade | 300 |
| 武器 | 疯魔模式 Psycho Mode | 350 |
| 毒物 | 毒瓶 Poison Vial | 70 |
| 毒物 | 蝎子 Scorpion | 40 |
| 工具 | 爆竹 Firecracker | 10 |
| 工具 | 开锁器 Lockpick | 50 |
| 工具 | 撬棍 Crowbar | 25 |
| 工具 | 尸袋 Body Bag | 70 |
| 工具 | 停电 Blackout | 250 |
| 工具 | 便签 Note（一次 4 张） | 10 |

商店界面只分三类槽位：武器（`weapon`）、毒物（`poison`）、工具（`tool`）。

### 6.2 多货币与经济系统

默认注册两种货币：

| 货币 | ID | 状态 |
| --- | --- | --- |
| 金币 | `wathe:money` | 默认启用，商店与 HUD 使用 |
| 任务币 | `wathe:task_money` | **定义与收益路径保留，但默认全部关闭**（HUD 不显示、单次收益为 0） |

**余额存储：** 金币沿用原版 `wathe:shop` CCA 的 `balance` 字段；其它货币写入同一组件上 AnnaWathe 追加的 `CurrencyBalances` NBT，跟随原版的同步、清理与重生策略，扩展不需要自己发包同步。

**价格模型：** `ShopPrice` 支持组合价——多个"方案（option）"之间是 **OR**，同一方案内的多种货币是 **AND**。玩家同时买得起多组方案时，选择**货币数量总和最小**的那组；总和相同时按定义顺序取靠前的。买不起时界面显示"或"与"免费"等本地化文本。

**被动收入：** 可以注册"哪些职业能拿被动收入""收入规则""收入数值修改器"，三者都遵循 `priority` 越大越优先、同优先级后注册者优先的规则链。

### 6.3 购买流程与服务端校验

客户端点击购买时**只发送商品索引**，不发送价格或物品信息。服务端收到后按顺序重新校验：

1. 重新解析该玩家当前的商店列表（含职业商店与所有修改器）；
2. 对局是否正在运行、玩家是否按玩法存活；
3. 索引是否越界；
4. 重新计算最优支付方案，余额是否足够；
5. 物品是否正在冷却。

**先交付、后扣款**：商品只有在成功交付后才原子扣除全部货币（先全量校验余额、再一次性扣、只同步一次），避免多货币支付出现"扣了一半月"的情况。扩展注册的购买回调**不允许自行扣款**。

> 开发环境有个便利设定：余额不足时会自动补到价格的 10 倍以便测试；正式服务器不会触发这条路径。

## 7. 疯魔模式（Psycho Mode）

原版疯魔模式被改造为**可注册 profile 的状态机**，默认 profile 等价于原版手感。

### 7.1 默认 profile 参数

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 持续时间 | **600 tick（30 秒）** | `PSYCHO_TIMER` |
| 护盾层数 | **1** | 可抵挡一次致命伤 |
| 授予物品 | 球棒（Bat） | 开启时自动放入快捷栏 |
| 近战击杀 | 开启 | 球棒满蓄力命中即击杀，死因 `wathe:bat_hit` |
| 锁定快捷栏 | 开启 | 期间不能切到别的槽位 |
| 锁定授予物品 | 开启 | 不能丢弃 / 不能换走 |
| 结束时回收物品 | 开启 | 精确回收本 profile 授予的物品 |
| 自动选中授予物品 | 开启 | |
| 皮肤 | `psycho.png` / `psycho_thin.png` | 按玩家模型自动选 slim / wide |
| 隐藏模型特征 | 开启 | 隐藏披风等普通特征，但**保留手持物** |
| 背景音 | `AMBIENT_PSYCHO_DRONE`，每 20 tick | |
| 命中音 / 护盾音 | `ITEM_BAT_HIT` / `ITEM_PSYCHO_ARMOUR` | |

**启动前置条件：** 授予物品数量不能超过快捷栏空格数，否则启动失败（不会把物品硬塞进满栏）。

### 7.2 护盾与可扩展点

- **护盾仲裁**：扩展可注册穿盾 / 特殊护盾规则；规则按 `priority` 排序取第一个非 PASS 的结果。没有规则命中时，回退为"护盾 > 0 则抵挡一次、否则不抵挡"。
- **锁栏三处防护**：滚轮换栏会回滚、数字键换栏会被拦截、服务端还会丢弃试图切到非锁定槽位的客户端包——防止恶意客户端绕过。
- **可注册的扩展点**：注册 profile、注册初始 profile 提供者、注册护盾规则、注册视觉 provider、注册背景环境音、替换疯魔皮肤、控制模型特征隐藏。
- **客户端幻觉物品**：低心情时观察者客户端会看到虚假的手持物与手臂姿势，这些状态**只存在观望者本地缓存**，死亡、停局、reset、断线都会清空，不写入任何存档。

## 8. 本能透视

本能的"资格"（能不能用）和"高亮"（目标什么颜色）被拆成两条独立的注册规则链，默认规则如下。

**默认资格（`annawathe:default_instinct`）：** 按键未激活时不干预；激活时，若玩家"能使用杀手功能且局内存活"或"处于旁观/创造视角"则启用。

**默认高亮（`annawathe:default_highlight`）实际颜色：**

| --- | --- | --- |

| 平民（心情 ≥ 0.55） | 局内存活 | `#4EDD35` 亮绿 |
| 平民（心情 0.2 ~ 0.55） | 局内存活 | `#1FAFAF` 青蓝 |
| 平民（心情 < 0.2） | 局内存活 | `#171DC6` 深蓝 |

## 9. 界面与 HUD

### 9.1 欢迎与结算界面

欢迎公告与胜负结算被完整重写，包含：

- **动态列数**：平民区用 5 列（人数多时自动分列），双分区（平民/杀手）用 3 列，孤行者用 6 列；
- **真实职业标题**、职业颜色、中立标题色 `#CC6600`（与原版 `RoleAnnouncementTexts.NEUTRAL` 一致）；
- **玩家头像**：带缓存与失败缓存，逐个异步请求皮肤；
- **死亡标记**：死亡玩家头像暗化 + 红叉；
- **独立胜利双分区布局**：支持自定义胜利的左右分区与分组标题；
- **文本自适应**：名字与职业标签超宽时自动缩放/截断（最小缩放 0.3），窄窗口自动减少列数，残行保持对齐；
- 欢迎/结束时播放原版音效序列。

### 9.2 准心与准心名字

- **准心**：原版 3x3 准心被完整接管。扩展可以注册"provider"替换默认准心（短路链，高优先级先执行），也可以注册"overlay"在默认准心之后追加小提示（不短路）。内置绘制工具包括标准普通/目标准心、匕首进度图标、棍棒进度图标、自定义 10x7 图标与进度条。
- **准心名字**：接管准心下方玩家名显示，可注册九类规则——是否显示 HUD、射线来源实体、玩家目标过滤、玩家名文本、非玩家实体名文本、同伙判定、同伙目标显示、同伙提示、额外 HUD。默认观察距离为旁观/创造 8 格、存活 2 格。
- **疯魔隐藏身份**：疯魔状态下的玩家名会显示为暗红色乱码 `urscrewed` 加随机字符。

### 9.3 心情 HUD

三套样式，均可由扩展注册替换：

| 样式 | 图标 | 说明 |
| --- | --- | --- |
| 普通（真实任务） | `mood_depressive` / `mood_mid` / `mood_happy` | 随心情切换图标，启用上下箭头，颜色按 HSV 随心情变化 |
| 职业色（伪装任务） | `mood_killer` 固定 | 无箭头，深红条 |
| 疯魔 | `mood_psycho` / `_hit` / `_eyes` | 高斯抖动、横向滚动文字「Kill them all!」、倒计时条、12 层残影 |

低心情（< 0.15）时显示 `annawathe.hud.mood.breakdown_warning`「精神即将崩溃」，并叠加随进度增强的抖动。

### 9.4 顶部计时

顶部回合倒计时被接管。默认 provider 只在"职业可见时间"或"旁观/创造 + 对局运行中"时显示。扩展可注册更高优先级的倒计时，支持动态变色、低时间警告与固定颜色；不同时间来源切换时会重置滚动数字动画。

### 9.5 商店余额与 Tooltip

- **余额显示**：右上角按货币逐行显示（`economy` 可见性由注册的谓词决定），余额归零时先播放归零动画再淡出，不会瞬间消失。
- **Tooltip**：统一定义物品的多行描述与**真实冷却读秒**。冷却直接读取当前 `ItemCooldownManager` 条目的 `endTick - tick`，**不用固定总冷却反推**，所以加速、减冷却等改动都能正确显示。AnnaWathe 已禁用原版 Wathe 的 Tooltip callback，其他扩展不要重复注册。

### 9.6 背包按钮与通用屏幕 HUD

- **背包按钮**：限制背包、普通背包、创造背包三类屏幕都支持挂载自定义按钮。每次打开屏幕创建独立的扩展实例，提供 `init` / `tick` / `render` / `allowInventoryKeyClose` / `close` 完整生命周期；动态控件用 group 管理，关闭时自动隐藏、禁用并解除焦点；页码状态按 ID 隔离并在断线、换局时清理。
- **通用屏幕 HUD**：三个绘制阶段——主 HUD 之前、Wathe 主 HUD 之后、整套 HUD 最后。适合职业状态文字、全屏黑幕、狙击镜等自由绘制。需要保留热键栏时通过受控入口复画，**不要**再去 Mixin 原版 HUD。
- **尸体信息 HUD**：显示"死亡时间 + 死因"整行与"身份"行，默认仅非存活观察者可见；两个字段可独立开关，职业名按注册名称 → Harpy 职业名 → 原版翻译键三级回退。

### 统一的规则语义

几乎所有 API 都使用同一套优先级语义，扩展可以放心组合：

- `priority` **越大越先执行**；
- `priority` 相同时，**后注册者优先**；
- 使用相同 ID 重复注册会**覆盖**旧规则；
- 结果枚举统一为 `PASS`（继续）/ 明确的终止值（`ENABLE`、`HIDE`、`ALLOW`、`DENY`、`SHOW` 等）。

### 三条硬性边界

1. **客户端视觉不能替服务端校验。** 准心、名字、HUD、皮肤、幻觉全部只是显示层；真实攻击、交互、购买、技能合法性必须在服务端重新判定。
2. **扩展不要重复 Mixin 已被接管的底层入口。** 准心、准心名字、通用 HUD、Mood renderer、时间 HUD、商店 renderer、结算 renderer、碰撞与存活判断都已被完整接管，请改用对应 API。
3. **扩展不要直接依赖 `bridge` 包或 Mixin 注入点。** 那些是 AnnaWathe 的内部实现，版本间可能变化。

## 12. 兼容性与已知边界

### 12.1 兼容性

| 对象 | 状态 |
| --- | --- |
| 原版 Wathe 1.3.2 ~ 1.4.1 | **支持范围**；1.4.1 亦已适配 |
| HarpyModLoader | **软兼容**：检测到才加载两个兼容 Mixin，用于强制职业的记账与中立职业优先分配；不装则完全不生效，也不作为依赖 |
| NoellesRoles / StupidExpress / StarryExpress | 不内置其职业规则；这些扩展需自己通过 API 注册胜利与任务 |
| 自改 Wathe | **不兼容**，禁止同时加载 |
| Iris / 光影 | 未在源码中做特殊处理 |

Harpy 兼容 Mixin 的一个实现细节值得一提：它只检查 Mod 元数据来决定是否生效，**不提前加载目标类**——因为提前加载会让 NoellesRoles 之后的注入失败。所有反射异常都被吞掉并保留原版行为。

### 12.2 明确的边界

- **不含体力系统。** `PlayerMovementApi` 只提供速度修正规则链（`ADD` / `MULTIPLY` / `OVERRIDE` / `PASS`），自改 Wathe 的体力消耗、心情体力惩罚、跳跃限制**没有**迁移过来。
- **不含停电、雾效、回放事件兼容**等机制。
- **部分 API 目前是骨架。** `TargetVisibilityApi` 在 AnnaWathe 内部**没有任何内置规则**（默认全部放行）；`VictoryApi` 也不内置具体职业规则；`CustomVictory` 当前没有内部调用方。它们是为扩展准备的接口，装上后不会自行改变玩法。
- **`PlayerMovementApi.canSelfMove` / `canJump` 恒返回 `true`**，且当前没有任何调用方，属于预留接口。
- **调试变形只改外观。** 不改变职业、阵营、声音、真实物品、碰撞或服务端身份；而且优先级低于职业伪装、幻觉视角等更高优先级的视觉规则。
- **`PlayerLifeStateApi` 只改玩法存活判断**，不改变原版 creative / spectator 的权限或物品消耗规则；普通 `/gamemode` 会撤销授权。
- **尸体外观不允许改真实 owner UUID**，真实 UUID 必须保留给验尸、尸袋、回放和死亡判定。

## 13. 已知问题与待办

以下问题在源码分析中发现，属于**当前版本的真实缺口**，记录在此便于后续修复。

### 13.1 `CustomVictory` 的 `fallbackTitle` 未赋值

`CustomVictory.Builder.build()` 没有给记录类的 `fallbackTitle` 字段赋值。如果扩展调用 `customWin` 时没有显式调用 `.fallbackTitle(...)`，且语言文件里缺少对应翻译键，结算界面会拼出 **"null Wins"** 这样的文本。`CustomVictoryGroup` 存在同样的问题。

**规避方法：** 注册独立胜利时始终显式调用 `.fallbackTitle(...)`。

### 13.2 `CustomVictory` 的分组标题未写入 NBT

`CustomVictory.writeToNbt` 序列化了 `announcement`、`detail`、`fallback`、`color`、`winners`、`group`，但**没有序列化 Builder 生成的 group `title` 翻译键**。结果是独立胜利数据经过一次 NBT 往返（例如存档重载、跨维度同步）后，分组标题会丢失并回退为 fallback 文本。

### 13.3 其他观察

- `MoodHudApi.shouldRender(GameMode)` 已在 API 中公开，但 AnnaWathe 内部从未调用——Mood HUD 的门禁实际由 `AnnaMoodRenderer` 自己按 `moodType != NONE` 判断。调用它不会出错，但也不会影响默认 Mood HUD。
- `VictoryBridge.capture()` 目前是空实现，仅作为扩展点保留。
- 心情数值常量中以注释形式保留了一个替代公式（按"3 分 20 秒"手算的版本），当前生效的是 `1 / getInTicks(3, 20)`。

> 如果你希望这些内容不出现在对外介绍里，删掉本章即可，其余章节不依赖它。
